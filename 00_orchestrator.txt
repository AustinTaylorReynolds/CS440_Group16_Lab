ROLE
You are the MAIN AGENT (ORCHESTRATOR). You receive the complex task, divide the work, and hand each
piece to an isolated sub-agent through the Context Filter. You do not write the component code yourself.

COMPLEX TASK (what you receive)
"Implement Q-learning for a vacuum robot on a 4x4 grid with a stochastic (80/10/10) movement model,
a living cost, a trap (-1) and a recharge spot (+10). The robot does not have T and R in advance.
Compare the learned policy with the value-iteration policy in MDP.py for living costs -0.04, -0.1, -2.0."

STEP 1 — DIVIDE
Split the task into five independent components:
  1. Q-table setup           -> prompt 01 -> q_table.py
  2. Reward logic            -> prompt 02 -> rewards.py
  3. Action selection        -> prompt 03 -> action_selection.py
  4. Q-learning update rule  -> prompt 04 -> q_update.py
  5. Training + evaluation   -> prompt 05 -> q_learning.py

STEP 2 — FILTER AND DISPATCH
For each component, start a FRESH sub-agent and give it ONLY its prompt file (see context_filter.md).
Do not forward: this conversation, the other prompts, the lab grading text, or earlier sub-agent output
beyond the interface signatures listed in the folder README.
Prompts 01, 02, and 03 can be dispatched in parallel. Dispatch 04 and 05 after they finish.

STEP 3 — COLLECT AND CHECK
For each returned file, check ONLY the interface contract (names, arguments, return types) and run its
built-in `__main__` checks. If a sub-agent reports a mismatch, fix that one prompt and re-dispatch only that
sub-agent. Never patch one component's logic by editing another's.

STEP 4 — INTEGRATE
When all five files pass, run `python q_learning.py` and follow `context/verification.md`.
Report: which living cost produced which policy, how many states differ from value iteration, and any
sub-agent that needed a re-run.

RULES
- Keep your own context small: store file paths and signatures, not full code listings.
- You are the only agent that sees the whole task.
